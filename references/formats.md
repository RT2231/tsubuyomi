# 入力形式ごとの読み取り方

e-Gov法令検索などでダウンロードできる4形式(XML / HTML / RTF / PDF横一段)と、論文などのPDF、URL、貼り付けテキストの扱い方です。
ファイルが `/mnt/user-data/uploads/` にあるのに中身が会話に見えていない場合は、まず `file-reading` スキルの案内も確認してください。

## 目次

1. XML(最優先)
2. HTML
3. RTF
4. PDF横一段
5. 論文などのPDF
6. URL・貼り付けテキスト
7. 条の分割(テキスト化した形式)
8. 読み取り後の確認

## 1. XML(最優先)

e-Gov法令XMLは条・項・号が構造化されているため、区切りの精度が最も高い形式です。複数形式があれば XML を優先します。

主なタグ(e-Gov法令標準XML):

| タグ | 意味 |
|---|---|
| `Law` / `LawNum` / `LawBody` | 法令全体 / 法令番号 / 本体 |
| `LawTitle` | 法令名 |
| `TOC` | 目次 |
| `MainProvision` | 本則 |
| `Part` / `Chapter` / `Section` / `Subsection` / `Division` | 編 / 章 / 節 / 款 / 目 |
| `Article` | 条(`Num` 属性に番号。枝番は `2_3` のような形) |
| `ArticleCaption` / `ArticleTitle` | 条文見出し / 条名 |
| `Paragraph` / `ParagraphNum` / `ParagraphSentence` | 項 / 項番号 / 項の本文 |
| `Item` / `ItemTitle` / `ItemSentence` | 号 / 号名 / 号の本文 |
| `Subitem1` など | 号の細分(イ、ロ…) |
| `SupplProvision` | 附則 |
| `AppdxTable` | 別表 |

読み取りの例(Python標準ライブラリ):

```python
import xml.etree.ElementTree as ET
tree = ET.parse(path)
root = tree.getroot()
for art in root.iter("Article"):
    title = art.findtext("ArticleTitle")
    caption = art.findtext("ArticleCaption")
    # 項・号は art.iter("Paragraph") / paragraph.iter("Item") で取得
```

注意(電波法の実ファイルで検証済み):
- **空白**:`Sentence` の中身にインデントや改行が入っている。`" ".join(text.split())` などで正規化してから使う。
- **ルビ**:`Ruby` の中の `Rt`(読み仮名)まで `itertext()` で拾うと、「較こう正」のように二重になる。本文は `Rt` を除いて読み、必要なら「較(こう)正」のように併記する。
- **附則の改正法番号**:附則が何の改正法によるものかは、`SupplProvision` の `AmendLawNum` **属性**にしかない。HTML・RTF・PDFでは「附則(昭和二七年七月三一日法律第二四九号)」と本文に表示されるので、XMLで読むときも見出しに補う。
- **条番号の重複**:`Article` の `Num` は本則と附則で重複する(本則の第四条と附則の第四条など)。`Num` だけをキーにせず、出現順や親要素(`MainProvision` / `SupplProvision`)と組み合わせる。
- **件数の数え方**:`iter("Article")` はドキュメント全体で数えると附則の条も含む。本則だけなら `MainProvision` の下で数える(電波法では本則326条+附則194条=520)。
- **表**:`TableStruct` のセルはテキスト化すると行・列の区切りが失われる。別表・表は行ごとに列を並べて示す。

## 2. HTML

- `BeautifulSoup` などで構造を読む。条は `section.Article`、附則は `section.SupplProvision`、別表は `section.AppdxTable`、章は `section.Chapter`。
- **画面用の部品を除く**:`._shokanBox` と `._inyoBox`(所管・引用ボタン用)は原文ではない。テキスト化の前に取り除く。
- **ルビ**は `<ruby>較<rt>こう</rt></ruby>` の形。`rt` を除いて本文を読み、必要なら併記する。
- **条名と第1項が同じ div に入る**:項が1つだけの条では、`div._div_ArticleTitle` の中に「第一条」と第1項の本文が一緒に入っている。条名だけが欲しいときは、先頭の `span`(太字)だけを取る。
- 全条の本文は、XMLと照合してルビを除けば全一致した。

## 3. RTF

- `extract-text file.rtf`(内部はUnicodeエスケープ)で読める。文字コードの心配は基本的にない。
- **重要な落とし穴:ルビの親文字が消える**。ルビは `{\field{\*\fldinst EQ ... \o\ad(\s\up 9({\fs10 こう}),\u-28925)}}` という埋め込みフィールドで表されていて、親文字(この例では「較」)がフィールド命令の中にしかない。そのまま `extract-text` や `pandoc` に通すと親文字が落ち、「較正」が「正」になる(電波法第24条の2で確認)。
  読む前に、フィールドを親文字だけに置き換える。

  ```python
  import re
  raw = open(path, "rb").read().decode("ascii", "replace")
  pat = re.compile(r"\{\\field\{\\\*\\fldinst EQ[^{}]*?\\o\\\\ad\(\\\\s\\\\up 9\(\{[^{}]*\}\),(\\u-?\d+)\)\}\}")
  fixed = pat.sub(lambda m: m.group(1) + " ", raw)   # 末尾は空白1つ(?を付けると余計な「?」が出る)
  open("fixed.rtf", "wb").write(fixed.encode("ascii", "replace"))
  # そのうえで extract-text fixed.rtf
  ```
- 変換後は、表がタブ区切りの行になる。**別表の行が「第○条」で始まる**ことがあるので、条見出しの検出には注意する(下の「条の分割」を参照)。
- 前処理をしたあとは、全条の本文がXMLと一致した。

## 4. PDF横一段

- 「横一段」は1段組の横書きPDF。文字情報があり(`pdffonts` で確認)、`pdftotext -layout` でほぼ読める。
- **ページ番号の行**(数字だけの行)と改ページ(`\f`)が本文の途中に混ざる。取り除いてから条を組み立てる。
- **条見出しの形**:「(条文見出し)」が前の行、「第一条 本文…」が次の行になる。
- **表(別表・表を含む条)は順序が崩れる**:列ごとの文字の並びが、原文どおりにならない(電波法の第4条・第65条・第71条の3の2などで確認)。表を含む条をPDFだけで読むときは、`pdftoppm` でそのページを画像にして、目で確認する。XMLかHTMLがあれば、表はそちらで確認する。
- **ルビ**は、親文字の少し前に単独の行として出る(「こう」が「二 別表第二に…」の前に出る)。
- 電波法のPDFでは、表を除く本文のほとんどの条がXMLと一致した(520条中、表・ルビを含む4条だけ不一致)。
- テキストがほとんど取れない場合はスキャン画像の可能性がある。その場合はOCRが必要になるため、ユーザーに伝える。

## 5. 論文などのPDF

- 2段組の論文は、単純な抽出だと段の順序が混ざる。段組を意識して抽出するか、ページ画像を確認する。
- 図表・式・脚注・参考文献も読み取り対象に含める。
- 章・節の見出しと段落の切れ目を手がかりに、「段落」単位に分割する。

## 6. URL・貼り付けテキスト

- URLは取得できる範囲で取得する。取得できない場合は、その旨を伝えて、ファイルのアップロードか貼り付けを依頼する。
- 貼り付けテキストは、番号や見出しを手がかりに区切る。

## 7. 条の分割(RTF・PDFをテキスト化した場合)

条見出しを行頭の「第○条」で検出すると、別表の行(「第二十四条の十一」で始まる表の行)も拾ってしまう。次のように見分ける。

- **RTF**:条見出しは「第○条」の直後が**全角空白**、別表の行は**タブ**。`^第…条(の…)*(?=　)` で検出すると、電波法の520条が漏れも余分もなく、順序どおりに取れた。
- **PDF**:条見出しは「第○条」の後ろが**空白1つ**、別表の行は**空白が何個も並ぶ**。
- どちらも、検出した条数と順序をXMLの条名の列(または目次)と照合して確かめる。

## 8. 読み取り後の確認

読み込みが終わったら、読み始める前に次を確認する:

- 条数(または段落数)が、目次や資料上の総数と合っているか(枝番号の条と、附則の中の条も数える)
- 附則・別表・参考文献などが取りこぼされていないか
- 文字化け、欠落、順序の乱れがないか

問題があれば、そのことをユーザーに正直に伝えてから読み進める。
